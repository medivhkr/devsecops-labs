# Сборка отчётов

Текст отчёта по каждой работе хранится в `labs/<папка>/report/report.json`. Из него собираются
DOCX и PDF по ГОСТ 7.32-2017: формат A4, поля 30/15/20/20 мм, Times New Roman 14 пт, интервал 1,5,
абзацный отступ 1,25 см, титульный лист КГТУ. Данные титульного листа заданы в `config.json`.

## Команды

```
python tools/report-builder/build.py labs/<папка>            # DOCX и PDF в каталоге reports/
python tools/report-builder/build.py labs/<папка> --no-pdf   # только DOCX
python tools/report-builder/build_all.py [--qa-dir DIR]      # все отчёты и проверка PDF
python tools/report-builder/fit_layout.py labs/<папка>       # подгонка вёрстки, см. ниже
```

Нужны Python 3 с пакетами Pillow, PyMuPDF и fontTools, Node.js с пакетом `docx` (`npm install`
в этой папке) и Microsoft Word: PDF экспортируется через Word скриптом `docx2pdf.ps1`.

## Структура отчёта

1. Титульный лист (`config.json` и `title_ru_lines`).
2. «Цель работы:» (блок `label`).
3. Задание: нумерованный список частей методички.
4. Оборудование и программное обеспечение: таблица «Компонент | Версия / параметры | Назначение»
   с версиями из протокола и описание стенда.
5. Краткие теоретические сведения со ссылками на источники `[1]`.
6. Ход работы: подраздел на каждую часть методички, рисунки с выводом терминала и листинги файлов,
   созданных в работе.
7. Ответы на контрольные вопросы, если они есть в методичке.
8. Выводы.
9. Список использованных источников по ГОСТ 7.0.100-2018.
10. Приложения (А, Б, …) для длинных листингов.

## Рисунки, листинги, таблицы

- Рисунок `terminal` строится из протокола `outputs/steps/*.txt`: `src` — файл шага или список
  файлов, `lines` — номера строк («1-40»; «1-4,...,12» — многоточие отмечает пропущенные строки),
  `caption` — подпись без точки в конце.
- В тексте на объекты ссылаются так: `{fig:id}`, `{tab:id}`, `{lst:id}`; номера подставляются при сборке.
- Подписи: «Рисунок N – …» по центру под рисунком, «Таблица N – …» и «Листинг N – …» слева над объектом.

## Источники

Оформление по ГОСТ 7.0.100-2018, например:

1. Lab - Use Ansible to Back Up and Configure a Device : лабораторная работа 7.4.7 // DevNet Associate v1.0 / Cisco Networking Academy. – 2020. – 11 с.
2. Ansible Documentation : [сайт]. – URL: https://docs.ansible.com/ (дата обращения: 14.11.2026).

## Формат report.json

```json
{
  "lab_id": "7.4.7",
  "title_ru_lines": ["Использование Ansible для резервного", "копирования и настройки устройства"],
  "blocks": [
    {"t": "label", "label": "Цель работы:", "text": "..."},
    {"t": "h1", "text": "Задание"},
    {"t": "numbered", "items": ["...", "..."]},
    {"t": "h1", "text": "Оборудование и программное обеспечение"},
    {"t": "p", "text": "Состав стенда приведён в таблице {tab:env}."},
    {"t": "table", "id": "env", "caption": "Состав лабораторного стенда",
     "header": ["Компонент", "Версия / параметры", "Назначение"], "widths": [3, 3, 4], "rows": [["...", "...", "..."]]},
    {"t": "h1", "text": "Ход работы"},
    {"t": "h2", "text": "Настройка Ansible"},
    {"t": "p", "text": "... показан на рисунке {fig:ver}."},
    {"t": "terminal", "id": "ver", "src": "steps/05_ansible_version_global.txt", "lines": "1-8", "caption": "Версия Ansible"},
    {"t": "listing", "id": "hosts", "caption": "Inventory-файл hosts", "code": "..."},
    {"t": "bullets", "items": ["...", "..."]},
    {"t": "note", "text": "..."},
    {"t": "h1", "text": "Выводы", "num": false},
    {"t": "p", "text": "..."},
    {"t": "sources", "items": ["...", "..."]},
    {"t": "appendix", "letter": "А", "title": "..."},
    {"t": "listing", "id": "full", "caption": "...", "code": "...", "font_size": 9}
  ]
}
```

Типы блоков: `h1`, `h2`, `h3` (`"num": false` — без номера, `"newpage": true` — с новой страницы),
`p`, `label`, `bullets` (маркер «–»; `;` и `.` в конце пунктов ставятся автоматически), `numbered`
(`"style": "dot"` даёт «1.», по умолчанию «1)»), `terminal`, `figure` (`image` — путь к PNG
относительно папки report), `listing`, `table`, `note`, `pagebreak`, `sources`, `appendix`.
В тексте допускаются `**жирный**` и `` `код` ``.

## Вёрстка

- Неразрывные пробелы («рисунок 5», «15 с», «[3]», инициалы, пробел перед тире) и неразрывные
  дефисы внутри коротких фрагментов кода расставляются при сборке.
- Поля `width_mm` у рисунков и `split_at` у таблиц выставляет `fit_layout.py`: он убирает пустые
  места перед рисунками (уменьшает рисунок не больше чем до 80 % или поднимает следующие абзацы)
  и добавляет надпись «Продолжение таблицы N» над перенесённой частью таблицы. Его запускают
  после всех правок текста.
