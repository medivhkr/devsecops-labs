## Как выполнялись работы

Каждая работа описана сценарием `labs/<работа>/scenario.yml`: команды идут в том же порядке, что
в методичке. Сценарий выполняется в GitHub Actions, и всё, что появляется в терминале, записывается
в протокол (`outputs/`). Отчёты составлены по этим протоколам, поэтому любой вывод команды из отчёта
можно найти в протоколе, а в `outputs/RUN.md` есть ссылка на сам прогон с полным журналом.

Устройство стенда:

- Лабораторная ВМ DEVASC воспроизведена контейнером Ubuntu 20.04 с пользователем `devasc`, именем
  хоста `labvm` и каталогом `~/labs/devnet-src` (скрипт `lab-env/setup-labvm.sh`). Версии Python 3.8
  и Ansible 2.9.6 совпадают с ВМ из курса. Работы, которым нужен systemd (sshd, apache2, сетевые
  службы), выполняются на ВМ Ubuntu 24.04.
- Маршрутизатор CSR1kv. Образ CSR1000v выдаётся только преподавателем (работа 7.0.3, шаг 1), поэтому
  в работах 7.0.3, 7.4.7 и 7.6.3 используется эмулятор командной строки IOS XE (`tools/csr1kv_emulator`).
  Он принимает SSH-подключения на адресе 192.168.56.101 с учётной записью из методички, а Ansible и
  pyATS работают с ним так же, как с настоящим устройством. Для перехода на реальный CSR1000v
  достаточно поменять адрес в inventory и testbed.
- Packet Tracer в CI запустить нельзя, поэтому работы 5.4 и 5.5 воспроизведены на сетевых
  пространствах имён Linux с теми же именами устройств, адресами и настоящими сетевыми службами.
- Симулятор School Library API из ВМ DEVASC не опубликован, для работы 4.5.5 он написан заново по
  описанию в методичке. Запросы из Postman выполнены консольным раннером Postman (Newman).
- Для работы 4.9.2 нужен личный ключ MapQuest. Приложение выполнено на открытых сервисах
  OpenStreetMap (Nominatim и OSRM), которым ключ не нужен, с теми же семью этапами, что в методичке.
  Вариант для MapQuest (`scenario.yml`) тоже подготовлен: для запуска нужны личный ключ в секрете
  `MAPQUEST_KEY` и workflow, описанный в `NOTES.md` этой работы.
- Для работы 3.3.11 создан отдельный репозиторий
  [devasc-study-team](https://github.com/medivhkr/devasc-study-team), в который сценарий отправляет
  коммиты по SSH с ключом развёртывания.

## Структура репозитория

```
labs/<NN>-<номер>-<тема>/
    scenario.yml          шаги работы
    prepare.sh            подготовка стенда до начала записи
    NOTES.md              соответствие шагов методички и отличия от неё
    outputs/              протокол: transcript.txt, steps/, files/, RUN.md
    report/report.json    текст отчёта
reports/                  готовые отчёты в PDF и DOCX
lab-env/                  лабораторная ВМ как код
tools/labrun/             запись терминальной сессии по сценарию
tools/csr1kv_emulator/    эмулятор маршрутизатора CSR1kv
tools/report-builder/     сборка отчётов DOCX/PDF по ГОСТ 7.32
.github/workflows/        прогоны работ и проверки безопасности
```

## Проверки безопасности

Workflow `security.yml` при каждом изменении запускает gitleaks (поиск ключей и паролей во всей
истории git) и bandit (статический анализ Python-кода). Учебные пароли из методичек (`cisco123!`,
`Cisco123!`) и образцы токенов из работы 3.6.6 внесены в исключения `.gitleaks.toml` с пояснением.
Ключ развёртывания для работы 3.3.11 хранится в секретах GitHub Actions и в репозиторий не попадает.
В программе работы 4.9.2 ключ MapQuest тоже не записан: он читается из переменной окружения
`MAPQUEST_KEY`, а в выводе URL заменяется на `key=***`.

## Как повторить

Любую работу можно перезапустить на вкладке Actions (Run workflow) или локально в Docker:

```bash
docker run --rm -it --hostname labvm --cap-add NET_ADMIN -v "$PWD":/repo -w /repo ubuntu:20.04 bash -c \
  "bash lab-env/setup-labvm.sh && bash labs/14-7.4.7-ansible-backup-config/prepare.sh && \
   python3 tools/labrun/labrun.py labs/14-7.4.7-ansible-backup-config/scenario.yml --out out/7.4.7"
```

Отчёт собирается командой `python tools/report-builder/build.py labs/<папка>`
(нужны Node.js с пакетом `docx` и Microsoft Word для экспорта в PDF).
